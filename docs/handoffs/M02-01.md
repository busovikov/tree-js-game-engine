# Handoff: M02 asset IDs, manifests, and decentralized registries

## Objective

Complete the breaking M02 transition from path/name identity and centrally owned component
schemas to UUID asset manifests, typed references, package-owned descriptors, and shared
composition-root registries without a legacy compatibility branch.

- [ ] Serializer, editor, and runtime use one registry assembled at their composition root.
- [x] Asset dependency closure is deterministic and tested.
- [x] Current repository builds, tests, lint, typecheck, dependency checks, and demo asset

- [x] Public manifest documentation and generated/example manifests match the implemented

## Decisions and invariants

- `AssetId`, `AssetTypeId`, component type IDs, and persisted references use UUIDs.
- Manifest paths are locations relative to `assetsDir`; only IDs are identity.
- Model loading accepts `AssetId`; filename-based vehicle presentation heuristics run only
  after resolving the ID to a manifest path.
- There is no parser branch for legacy string `entryScene` or string `modelAsset`.
- Scene component envelopes are generic UUID/type/data records. Unknown component IDs fail
  through `ComponentDiagnosticError`.
- Registries must be injected/assembled at composition roots in the remaining slice. Do not
  reintroduce a process-global mutable registry.
- Do not start M03 scheduler or activation work.

  `createCoreComponentRegistry()` internally.

- Decide and implement the M02 prefab asset boundary: repository scenes currently retain an

  add positive and negative tests before conversion.
- Re-run stale schema ownership/import searches, full verification, a browser smoke check,
  and update the M02 status/acceptance checkboxes only after these remaining items are green.

## Risks and open defects

- M02 is partial. Starting M03 now would build scheduler work on the wrong registry/package
  boundary.
- Serializer defaults create a fresh core registry, so the “same registries” acceptance item
  is not yet met even though injection is available.
- `AssetRegistry` is not yet connected to runtime/editor composition.
- Editor playground rename writes the destination but retains the pre-existing best-effort
  disk behavior for removal of the old file; this was not expanded because it is separate
  filesystem lifecycle work.
- Formatting the manifest migration touched existing densely formatted source while applying
  the repository Prettier configuration; all semantic and verification checks are green.
