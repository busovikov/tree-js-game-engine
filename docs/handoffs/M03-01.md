## Decisions and invariants

- `activeSelf` is authored and serialized, defaults to `true`, and is never overwritten by
  ancestor activity.
- `activeInHierarchy` is runtime-derived from `activeSelf` and ancestor activity.
- Deactivation traverses children before parents; activation traverses parents before
  children. Component hooks within an entity use component-type UUID order.
- Component lifecycle is optional and deterministic:
  `create`/`activate`/`deactivate`/`destroy`.
- `IWorld.query()` excludes inactive entities. Only explicit diagnostic or authoring code
  uses `queryIncludingInactive()`.
- `EngineScheduler` is the sole owner of frame/fixed time, accumulator, bounded catch-up,
  frame/tick numbering, pause, single-step, phase order, and interpolation alpha.
- Phase order is `FrameInput`, `AccumulateTime`, bounded repetitions of
  `FixedInputSnapshot`, `FixedPrePhysics`, `PhysicsStep`, `PostPhysics`, `FixedGameplay`,
  then `FrameGameplay`, `LateUpdate`, `Presentation`, and `Render`.
- Systems order by finite `localOrder`, with registration sequence as the stable tie-breaker.
  Numeric global system order and fractional magic offsets are removed.
- Typed queued commands capture target/source phase, source tick/frame, stable sequence, and
  payload. Same-phase enqueue waits for the next phase visit and cannot execute reentrantly.
- `PhysicsWorldSystem` performs exactly one backend step per `PhysicsStep` and owns no
  accumulator. Presentation interpolation consumes the scheduler alpha.
- `ENGINE_SCHEDULER_POLICY` remains 60 Hz, at most three substeps, and at most 50 ms admitted
  frame time.
- M04 must reuse these contracts. It must not add a graph loop, graph accumulator, or
  synchronous cross-domain execution.
