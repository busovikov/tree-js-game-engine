## Decisions and invariants

- Graph assets contain only strict serializable Haku data. Haku-owned layout is
  `{ x, y, width?, height?, collapsed?, label? }`; React Flow state is rejected recursively,
  including inside generic properties and metadata.
- Stable UUIDs identify graph, node type/instance, port, callsite, connection, and data type
  contracts.
- `flow`, `event<T>`, `trigger`, and `data` are distinct. `trigger` has no stored value.
  Incompatible data requires an explicit conversion node.
- Same-domain flow remains a plan flow edge. Events are scheduled queue operations, and
  cross-domain flow becomes a queue operation. Cross-domain data is rejected.
- Data dependencies are deterministically topologically ordered; data cycles are compile
  errors. Runtime flow-loop limits remain M05 work.
- `NodeRef<TContract>` serializes only a node UUID and may resolve only inside the current
  graph instance. It does not add an execution edge.
- Visual and TypeScript-schema data types share the same plain `DataTypeContract`; a
  TypeScript definition without a runtime Zod schema cannot be registered.
- Registry fingerprints cover sorted type and node contracts. Plans carry the combined
  fingerprint and are rejected when it differs.
- Custom Node definitions contain metadata and a capability-gated context type only. They
  contain no execute callback and receive no engine internals in M04.
- Unknown/external effects and dynamic resource reads are retained as explicit
  checkpoint-ineligibility causes. Missing capabilities are compile errors.
- The compiler depends only on schema/assets/core contracts. It neither imports nor executes
  React, React DOM, Three.js, editor code, or graph-runtime code.
