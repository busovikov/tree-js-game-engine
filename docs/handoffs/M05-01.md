# Handoff: M05 graph interpreter, domains, queues, and tracing

## Objective

Record the completed M05 headless graph runtime. `@haku/graph-runtime` interprets
registry-bound compiled plans through the existing `EngineScheduler`, owns graph-instance
lifecycle and structured tasks, freezes lazy data snapshots, and exposes deterministic
tracing and structured failures behind a replaceable execution backend. Checkpoint/rewind
remains exclusively M06 work.

## Scope and acceptance criteria

- [x] Add `@haku/graph-runtime` without React, Three.js, editor, or another game clock.
- [x] Interpret compiled same-domain flow plus queued cross-domain flow/events.
- [x] Execute through every existing scheduler domain without synchronous reentry.
- [x] Lazily cache data dependencies against stable parameter/resource snapshots.
- [x] Support public parameters, outputs, events, subgraphs, and read-only same-instance
      `NodeRef`.
- [x] Hold async branches for explicitly owned children and cancel them with lifecycle.
- [x] Cancel tasks, queued continuations, child instances, and subscriptions on
      deactivate/stop/destroy.
- [x] Emit deterministic traces, structured node errors, and bounded runaway errors.
- [x] Keep interpreter dispatch replaceable through `ExecutionBackend`.
- [x] Pass targeted and full repository verification.

## Decisions and invariants

- `EngineScheduler` remains the only owner of time, fixed accumulation, phases, tick/frame
  numbering, and queue sequence. Graph runtime owns no loop or accumulator.
- Same-domain flow may continue immediately after its source completes. Cross-domain flow
  and every event edge enter `EngineScheduler.enqueue`; lifecycle generation checks make
  stale queued continuations no-ops.
- Runtime follows compiled connection order and refuses a registry mismatch before
  construction. Callers may also require an exact plan fingerprint.
- Plans now retain public-interface and node kind/execution/exported-state metadata. They
  still contain no executable callbacks.
- Node execution is registered outside `@haku/graph` by node type and version.
  `InterpreterExecutionBackend` is only one implementation of the public
  `ExecutionBackend` boundary.
- Each execution freezes public parameters and declared resource values. Cache identity
  includes scheduler frame/tick/phase and typed parameter/resource invalidation revisions.
  Mutations during evaluation become visible only to a later snapshot.
- Ordinary async nodes and `spawnChild` tasks hold their branch. Deactivate, stop, and
  destroy abort their shared scope and suppress cancelled downstream flow.
- A subgraph is a compiled child plan with an isolated instance/public API and parent-owned
  lifecycle. It does not expose internal nodes to its parent.
- `NodeRef` can read only declared exported state from a node in the same instance and
  returns a clone.
- Trace entries contain deterministic sequence, graph/instance/node, phase, tick/frame,
  effects, safe input identity/output keys, queue connection, and task/error state. They do
  not use wall-clock timestamps.
- Runaway flow/event feedback shares a bounded execution budget, including queued
  continuations.
- No M06 checkpoint records, rewind, queue removal, async checkpoint policy, persistence,
  or migration code was added.

## Risks and open defects

- Scheduler-owned queued commands do not yet expose removal by checkpoint sequence. M05
  cancellation safely makes stale work a no-op; M06 must add atomic post-checkpoint queue
  removal without adding another queue or clock.
- Runtime values travel through compiler-typed callsites, but project runtime-schema value
  validation at external adapter boundaries should remain explicit as later capabilities
  are introduced.
- The current apps do not yet compose authored graph instances. That user-visible diagnostic
  integration is M07, after M06 checkpoint semantics.
- Checkpoint/rewind, effect reconciliation, async checkpoint policies, persistent records,
  migration, and fallback are intentionally absent.
- Existing Rapier deprecation warnings and Vite bundle/import warnings remain unrelated
  baseline warnings.
