Record the completed M06 headless checkpoint foundation. The graph compiler proves bounded
checkpoint-local state scopes, dynamic-physics/query/effect eligibility, and async
liveness/dominance metadata. `@haku/graph-runtime` owns one checkpoint per root instance,
rewinds atomically through the existing scheduler and execution scope, enforces all seven
async policies at stable callsite UUIDs, reconciles one-shot effects, and exposes a

## Decisions and invariants

- `EngineScheduler` remains the only queue, phase owner, game clock, fixed accumulator, and
  tick/frame source. Rewind uses its queue sequence watermark and selective removal hook.
- Checkpoint eligibility is local to each proven transitive scope. Rapier state, dynamic
  bodies, dynamic contacts/queries, and unprovable queries are never snapshotted.
- `GraphInstance.createCheckpoint()` is an async barrier and replaces the prior checkpoint
  only after policy validation/capture succeeds.
- Async selections are keyed by compiler-emitted callsite UUID. Restart declares
  pure/idempotent safety plus persisted inputs; resume declares a state-machine ID/state;
  reconnect declares durable operation ID/status; materialized requires a completed
  snapshot-safe result; cancel requires an `Option`/`Result` fallback; reject and wait
  timeout return typed `CheckpointPolicyError`.
- In-flight and restored tasks remain in the graph instance's owned task set and retain the
  abort signal from their original lifecycle generation.
- Rewind restores only scoped parameters, outputs, exported node state, declared resources,
  and async/effect records. Stable effect IDs prevent one-shot replay.
- Persistent checkpoint records include checksum and plan, registry, scope, and reference
  fingerprints. Registered migration runs before resume. Successful persistent restore
  dispatches `resume-from-checkpoint` instead of start flow.
- `SaveService` reads/writes one checkpoint entry by slot and graph instance. M06 adds no
  IndexedDB, slot storage, replication, cloud, or platform implementation; those remain
  M10d.
- An incompatible record invokes only that graph's fallback entry. The runtime neither
  deletes the record nor mutates unrelated save-slot data.

  identity intentionally makes it a distinct delivery.
- `SaveService` is only an integration contract. Durability, transactional slot writes,
  quotas, replication, and cloud conflict handling are deferred to M10d.
- Existing Rapier deprecation warnings and Vite chunk/import warnings remain unrelated
  baseline warnings.
