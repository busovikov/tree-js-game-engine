## Decisions and invariants

- The iframe sandbox token is intentionally only `allow-scripts`. MDN documents that omitting
  `allow-same-origin` gives the document an opaque origin, while `allow-scripts` permits code
  execution. Do not add same-origin, popup, navigation, or file-system permissions.
- The opaque-origin bootstrap receives one transferred port through
  `window.postMessage(..., "*", [port])`; all later traffic uses that dedicated channel.
- Capability data is recursively restricted to finite JSON scalar/array/plain-object values,
  then cloned before transfer. Runtime never receives editor objects or browser file handles.
- `ProjectService.openCodeWorkspace()` is the storage/trust composition boundary. Reopening any
  project clears the prior workspace reference.
- Native workspace discovery includes `.haku/generated` while skipping `.git`, `node_modules`,
  and `dist`. In-memory files use logical revisions so external writes are conflict-visible.
- Generated-file persistence only accepts `tsconfig.json` and `.haku/generated/*`.
- Official sources carried forward:
  - https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe
  - https://developer.mozilla.org/en-US/docs/Web/API/MessageChannel
  - https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage
  - https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/getFile
  - https://developer.mozilla.org/en-US/docs/Web/API/FileSystemHandle/queryPermission

## Risks and open defects

- `browser-bundle.worker.ts` still externalizes public `@haku/*` imports. Play needs an explicit
  browser-safe runtime import strategy before bundles using those imports can execute.
- Unit timeout proves cleanup orchestration, but a synchronous infinite loop inside an iframe may
  monopolize its renderer thread. The real Chrome runaway scenario must prove that the parent
  remains responsive; if it does not, execute the bundle in a terminable Worker owned by the
  sandbox frame while keeping DOM/file handles unavailable.
- The iframe Blob-module import and opaque-origin behavior have not yet run in Chrome.
- Successful module import is currently a terminal success and removes the iframe. If the final
  gameplay lifecycle needs a persistent frame, split protocol messages into `ready` and terminal
  `stopped` while retaining explicit disposal tests.
- Native recursive workspace discovery is typechecked but not yet exercised against a real
  File System Access directory handle.
- The external VS Code helper still requires a user-supplied absolute path because directory
  handles do not expose one.
