## Decisions and invariants

- `CodeWorkspacePanel` depends on replaceable editor/language/bundler/Play interfaces. Monaco,
  TypeScript, esbuild, and the iframe transport are composition details.
- Generated declarations and `tsconfig.json` are shared tooling inputs, not editable source.
  Only TypeScript source/declaration files become Monaco language models.
- Trust/capability diagnostics run before Worker or Play creation. Imported code is never
  compiled merely to discover that it is untrusted.
- Public `@haku/node-sdk` imports resolve to a browser-safe virtual runtime in the gameplay
  bundle; editor packages and Node built-ins remain unavailable.
- Dev-target writes pass through to disk. Reads used for open/save/reload come back from disk
  with `mtimeMs` and byte size, rather than trusting the browser-store revision.
- Play remains an opaque-origin `sandbox="allow-scripts"` iframe. A synchronous runaway was
  allowed to reach the ten-second timeout in real Chrome; the parent renderer and editor stayed
  responsive and the iframe was removed.
- Monaco explicitly uses its stable textarea input path (`editContext: false`) for consistent
  browser/editor input rather than its experimental EditContext path.

  coverage and visible UI coverage, but not an automated picker/application round trip.
- Imported-untrusted behavior requires a folder-picker project, so its exact pre-client denial
  is covered by the injected UI test rather than an automated native-picker Chrome scenario.
- Editor-extension bundles exist as an M08 build boundary, but their component metadata,
  constrained gizmo/widget APIs, and runtime loading belong to M09.
- Production editor chunks are large. M08 proves lazy editor/game separation, not final editor
  download budgets; those remain deferred program work.
