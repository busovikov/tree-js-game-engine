## Decisions and invariants

- A project component type uses one stable UUID as both its component type ID and manifest asset
  ID. The asset type UUID is
  `20000000-0000-4000-8000-000000000008`; graph assets retain `...0007`.
- Component data is strict, serializable plain data. The registry definition owns schema,
  defaults, fingerprint, reference metadata, Inspector metadata, optional behavior attachment,
  and optional editor-extension descriptors.
- Scene commands resolve component definitions from the world. Editor commands must not fall
  back to an engine-only registry and silently drop project components.
- TypeScript behavior is an explicit scheduler system with domain/query/reads/writes/effects and
  public add/set/remove commands. Its update callback receives the complete entity batch once.
- The Inspector trace action runs the real core `ComponentBehaviorRunner` with a non-mutating
  preview callback. It exposes the declared contract and entity count; it does not execute the
  project bundle export.
- Graph data types and Get/Set/Add/Remove nodes derive stable UUIDs from the component type,
  declare world resources/effects, and register idempotently into the existing Graph Editor
  registries.
- `GizmoProvider` receives only entity/type/plain-data context and returns validated line,
  sphere, or box primitives. Edits re-resolve the schema and use `commitSceneEdit`.
- The custom widget is an opaque-origin `sandbox="allow-scripts"` iframe with
  `default-src 'none'`; its message boundary accepts only a finite numeric `speed` patch.
- Imported-untrusted editor extensions and behaviors remain inert and visibly unresolved.
- No M10 packages or compatibility layers may be introduced.

## Risks and open defects

- Scene and prefab manifest dependency collection currently finds `AssetRef` values inside
  component data but does not treat a custom component envelope's `type` UUID as a dependency
  on its Component Type asset. A closure-based export can therefore omit the definition.
- The Inspector trace is an honest non-mutating contract preview through the core runner; it
  does not load or execute the named TypeScript export from the gameplay bundle. Full project
  bundle registration may require a later runtime composition point, but must not broaden the
  editor sandbox authority.
- Graph registries add project contracts idempotently but do not remove stale contracts when
  switching between projects or replace a changed definition that reuses the same UUID.
- The visual dialog authors number/string/boolean fields. Vector/color/reference field support
  exists in the asset schema and generated Inspector, but is not yet exposed in that dialog.
- The example gizmo is represented in the Inspector as validated primitive output; it is not
  yet drawn into the Three.js viewport.
- No full repository gates, production scans, or Chrome checks have run after these M09 commits.
