## Decisions and invariants

- A project Component Type owns one UUID used as both component type ID and manifest asset ID.
- Scene and prefab manifest dependency writes combine ordinary serializable `AssetRef` values
  with references derived from registered custom component envelopes.
- Inspector behavior tracing runs the real core `ComponentBehaviorRunner` with a non-mutating
  preview callback. It proves the declared batch/scheduler contract and entity count; it does
  **not** execute or claim execution of the named TypeScript export from the gameplay bundle.
- Gizmo providers receive only entity ID, component type, and plain component data. Their
  output is limited to strict line/sphere/box primitives; component patches re-parse through
  the schema and enter `commitSceneEdit`.
- The example widget is an opaque-origin `sandbox="allow-scripts"` iframe with
  `default-src 'none'`; only a finite numeric `speed` patch crosses its message boundary.
- Imported-untrusted behavior/editor code never loads. The UI renders unresolved/inert state.
- No engine package, viewport Three.js renderer, M10 package, push, PR, or history rewrite was
  introduced.

## Risks and open defects

- The Inspector trace deliberately validates/runs the declared core batch contract with a
  non-mutating preview callback; executing the named project TypeScript behavior export still
  requires a future trusted runtime composition point. Documentation now states this exact
  boundary instead of implying execution.
- Project graph registries register Component Type contracts idempotently but are append-only;
  a future multi-project editor session should replace/remove stale project contracts rather
  than reuse one global registry indefinitely. The single-project Chrome flow did not expose
  stale contracts.
- Visual Component Type authoring currently offers number/string/boolean fields. Vector,
  color, entity, asset, and component reference support exists in schema/generated Inspector
  contracts but not yet in the dialog.
- The constrained gizmo example is visible in Inspector and fully undoable, but is not drawn
  into the Three.js viewport. This preserves the M09 no-Three extension boundary.
- Chrome automation could not complete the prefab-name `prompt()` interaction; automated
  persistence/closure tests are the authoritative prefab evidence for this pass.
