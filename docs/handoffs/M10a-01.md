## Decisions and invariants

- `PoolHandle` uses the graph type's existing `pool/entity/generation` shape. Reacquire
  increments generation, so stale and cross-pool releases cannot affect a live lease.
- Pooled entities stay in `IWorld`; only each instance root is deactivated.
- Baselines parse component data through the registered component schema, restore authored
  names/parents/activity/components, recreate missing authored entities, and remove
  runtime-added descendants/components.
- Release deactivates before lifecycle dispatch. Lease scope aborts tasks, runs cleanup in
  reverse order, clears flags, and is reset before reuse.
- Graph instances are destroyed on release and recreated on acquire. The engine participant
  synchronously reconciles `RenderSyncSystem` and `PhysicsColliderSystem`; reacquire therefore
  creates a new zero-velocity body.
- Audio remains an M10c subsystem. It plugs into the general `PoolLifecycleParticipant`
  boundary; M10a did not create audio code.
- The serializable component references a prefab asset. Runtime composition uses the owner
  entity UUID as pool ID and an injected prefab resolver, preserving package boundaries.
- Acquire/release/prewarm/release-all/clear graph nodes declare the bounded `pool` resource and
  `pool` effect; metrics is a read-only checkpoint-safe node.
- The playground change is a headless console diagnostic, not a visible composition change;
  Chrome was therefore not applicable under the M10a instruction.
