## Decisions and invariants

- A UI asset has one asset UUID, one root container UUID, and a flat strict element table.
  Container child UUIDs form the validated hierarchy; duplicate, missing, multiply-parented,
  cyclic, and unreachable elements are rejected.
- `UIDocumentInstance` uses native semantic DOM elements (`div`, `span`, `button`, `img`) and
  no React. Native button disabled/keyboard behavior, image alt text, hidden/inert state,
  accessible labels/live regions, flex layout, sizing, absolute anchors, base styles, and
  theme overlays come from serializable data.
- Image paths never enter UI documents. Images hold typed asset references and runtime URLs
  come from an injected resolver. The UI asset descriptor contributes those references to
  dependency closure.
- `UIService` owns registered/mounted documents. Graph adapters and `createUISdk()` can only
  call its public text/visibility/enabled/theme mutations and subscribe to typed activation
  events.
- Four UI graph mutations declare only the `ui` capability/resource/effect, bounded scope,
  and checkpoint-visible effect records.
- React visual authoring stays in `@haku/editor`; `@haku/ui` has an ESLint guard against
  React, React DOM, and editor imports.
- UI authoring state (selection and viewport preset) is not serialized. Every hierarchy or
  Inspector edit replaces a strict document through `CommandBus`; save/reload uses
  `projectService` and manifest dependency refresh.
- Official platform grounding used MDN DOM creation/tree APIs, CSS flex/positioned layout,
  hidden/inert/disabled/image-alt APIs, DOM event dispatch, and W3C APG button/accessibility
  naming guidance.

  root should explicitly become the containing block before the browser diagnostic.
- Normal project image preview resolves manifest paths to project URLs. Native file-backed
  image preview may need the existing project blob resolver pattern if Chrome exposes a
  failure; do not embed file paths in the asset as a workaround.
- The visual panel edits text inputs on each change, producing granular commands. This is
  correct for undo but may merit command coalescing later; it is not required for M10b.
