## Decisions and invariants

- `@haku/audio` has no DOM or Web Audio dependency. `@haku/audio-web` is the only package
  that owns `AudioContext`, AudioNodes, decoding, and autoplay unlock.
- An `AudioClip` is runtime metadata plus optional in-memory bytes. Its registered manifest
  asset descriptor parses `Uint8Array` and contributes no remote/path dependency.
- `AudioSource` holds a typed Audio Clip UUID reference. Category routes are always
  `Music|SFX|UI -> Master`; runtime handles and decoded buffers never enter serialized data.
- Global pause is backend suspension. Audible playback is not unlocked automatically:
  `WebAudioBackend.unlock()` must be invoked directly inside a real user gesture.
- Spatial playback uses `PannerNode.positionX/Y/Z` AudioParams. Deprecated
  `PannerNode.setPosition()` is not used.
- A single Web Audio backend owns one context and one persistent bus graph; each playback
  creates a fresh one-shot `AudioBufferSourceNode`, as required by the platform API.
- Entity/pool ownership reuses `PoolLifecycleParticipant`; audio does not add pool-specific
  ownership inside `@haku/pool`.

## Risks and open defects

- `AudioSourceComponent.defaults()` currently uses a sentinel UUID because a required clip
  cannot be inferred generically. Editor Add Component must select a real clip before
  persistence, or the component creation contract should be tightened in the next slice.
- Web Audio local mute/unmute has no remembered unmuted gain yet; add a failing regression
  test before relying on it in the preview.
- `setPaused()` intentionally keeps the synchronous backend interface and currently starts
  `suspend()`/`resume()` without surfacing promise rejection. The service slice should expose
  an observable async error/status path.
- Listener pose is not implemented yet; source Panner positions are covered headlessly.
- Engine asset/component registries do not yet include audio, so scenes and manifests cannot
  consume the new model until the next composition slice.
