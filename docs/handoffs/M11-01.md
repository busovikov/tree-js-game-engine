## Decisions and invariants

- The scheduler remains the sole simulation clock: ball control is `FixedPrePhysics`, Rapier
  contacts are consumed in `PostPhysics`, failure is `FixedGameplay`, and the camera is
  presentation-only `LateUpdate`.
- Landing validity is derived from a monitored collision enter, a sufficiently upward
  world-space contact normal, and downward pre-step velocity. A fixed tick can emit at most
  one landing.
- Bounce velocity is analytic (`sqrt(2gh)`) and is applied on the next fixed pre-physics step.
- The graph variable store owns session state. App composition translates user/physics events
  to public graph entry paths but does not duplicate the state machine.
- All four HUD panels are manipulated by real UI graph nodes. The shared UI runtime now removes
  hidden flex containers from browser layout, preventing invisible overlays from intercepting
  input.
- The six platforms come from the authored prefab and `EntityPoolComponent`; app code provides
  only the public prefab resolver and initial finite sequence placement.
- The HUD JSON is fetched from its project asset URL and schema-parsed at runtime. Tests inject
  the same authored JSON through the fetch seam.
- CCD is enabled on the dynamic ball because Rapier leaves it disabled by default and the game
  combines gravity, forward motion, and thin landing surfaces.
