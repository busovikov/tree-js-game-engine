## Decisions and invariants

- Bounce-specific report schemas stay in `apps/bounce-run`; the reusable canonical clone/string/hash
  primitives remain in `@haku/core` and were not duplicated.
- A session report accepts exactly one current-version recording. Observation snapshots must be
  strictly increasing and within its tick range; every supplied result array is recomputed from the
  same snapshot and global declarative assertion specifications.
- Runtime and console errors share one strict record with source, category, message, optional tick,
  and optional finite JSON-only bounded context. Network collection belongs to the future browser
  harness, not this pure report schema.
- `serializeBounceRunBugReport` revalidates and clones its input, then encodes
  `stableCanonicalStringify` with `TextEncoder`; it does not create Blob, object URLs, anchors, files,
  or downloads.
- Existing graph `Assert`, replay hashes, observation semantics, and runtime public APIs were not
  changed.
- The current production build contains no report sentinel only because the new module is unwired.
  This is useful smoke evidence, not acceptance proof for the next dev-only wiring change.
- No browser, Playwright, editor/React, audio, storage, M13, M14, or `main.ts` code was opened or
  changed in this slice.
