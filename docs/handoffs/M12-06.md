## Decisions and invariants

- `createBounceRunQaHarness` is reusable data-only orchestration. It receives subscription/read
  ports, not engine objects, and reconstructs the existing fixed-tick recorder only when composing
  an immutable report.
- Browser runtime composition stays app-local and dev-only. Its global and DOM bridges expose only
  named gameplay actions, read snapshots, and report composition; neither exposes runtime mutation
  objects or setters for world/entity/pool/physics state.
- The explicit bounded lateral action is a normal public `BounceRunInputSystem` action port. It is
  validated to `[-1, 1]` or `null`, participates in the same fixed control system as keyboard input,
  and is cleared by normal run reset.
- Console wrappers, runtime listeners, and the fetch wrapper are installed only in the DEV chunk and
  restored conditionally on dispose. Diagnostics are stable-order, exact-deduplicated, finite plain
  data and bounded by the existing report limits.
- The user-Chrome surface provides a restricted read-only evaluation realm that does not reveal
  arbitrary page globals. The DEV-only namespaced DOM bridge therefore provides accessible action
  controls and a JSON artifact node without broadening production or game-state authority.
- Vite's official documentation states that `import.meta.env` constants are statically replaced at
  build and code inside `if (import.meta.env.DEV)` is tree-shaken in production:
  https://vite.dev/guide/env-and-mode.html
- Vitest sets `NODE_ENV=test`; Vite documents every non-production `NODE_ENV` as `DEV=true`.
  Therefore the authoritative production regression explicitly spawns the real build with
  `NODE_ENV=production` before scanning its emitted JavaScript.
- This slice is a narrow smoke only. It did not add Playwright or implement a workflow matrix.

## Risks and open defects

- The DOM bridge is intentionally DEV-only and visible so the restricted Chrome agent realm can use
  it; production exclusion is authoritative and executable.
- The narrow Chrome run used the explicit public lateral action port because discrete OS keypresses
  did not persist across a fixed snapshot. The next automated matrix must prove sustained real
  keyboard keydown/keyup behavior through Playwright rather than treating this smoke as that proof.
- The report's last fixed-tick observation remains `active` when Escape pauses before another fixed
  tick; the production UI's visible `Paused` state is authoritative for this smoke. The full matrix
  should assert both the visible paused state and the absence of additional fixed ticks while paused.
- Rapier still emits its known initialization compatibility deprecation warning.
