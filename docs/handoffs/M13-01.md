## Decisions and invariants

- Platform decisions consume only the platform RNG. Bonus placement uses `seed ^ 0x9e3779b9` after
  the mandatory route is complete, so enabling a bonus cannot perturb platform decisions.
- Bonus transition selection is bounded by `minimumPlatformCount`, not the requested final horizon.
  Once that minimum is present, longer routes preserve the exact bonus descriptor and decision.
- `BounceRunRoutePlatform.behavior` is the future runtime contract: `standard` uses the common
  gameplay bounce height and `boost` carries the authored higher bounce height. This stage does not
  pretend the current runtime already applies it.
- The bonus is deliberately optional lateral risk: analytic contact is reachable with steering,
  while `mandatoryPathClearance >= sensorClearance` proves a no-input center-line run cannot collect
  it accidentally.
- Exactly zero bonuses are emitted when bonus config is absent/disabled or the route is shorter than
  `minimumPlatformCount`; exactly one is emitted otherwise.
- Existing mandatory-route fallback remains centered, deterministic, and bounded even for variant
  platforms. There is no compatibility or horizon-rewrite layer.
