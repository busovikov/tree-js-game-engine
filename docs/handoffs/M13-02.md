## Decisions and invariants

- Route descriptors are runtime data on active lease views; Three.js objects never enter component or
  gameplay data.
- Pool acquire initialization changes `MeshRenderer`/`Collider` component data before the engine pool
  lifecycle participant reconciles render and physics. Release uses the same engine lifecycle, which
  disposes the prior geometry/body; no geometry is created per frame.
- Bonus claims live with the route lease lifecycle. Score itself lives only in graph variables.
- Physics event entity IDs have no pool generation. The collector therefore requires both a current
  active lease mapping and a current geometric overlap; an old enter after reset/reuse cannot collect
  a far-away reacquired sensor.
- No new graph node or capability was needed: foundation Add plus deterministic Get/Set Variable own
  scoring. UI/save work must continue through their existing public graph/service seams.
- QA observation changed to version 2 because its public session shape now includes score.
