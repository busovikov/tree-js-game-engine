## Decisions and invariants

- Vite `base: './'` is the minimal production HTML/module portability setting. Official Vite docs
  define `./` or an empty string for embedded deployments and state that a relative base makes
  generated HTML, CSS, and JavaScript asset URLs relative to each file:
  <https://vite.dev/config/shared-options#base> and
  <https://vite.dev/guide/build#relative-base>.
- Vite cannot rewrite application-computed fetch strings. The shared `projectPathToUrl()` therefore
  emits document-relative URLs, which fixes scene and prefab consumers in Bounce Run, playground,
  and create templates without a game-local compatibility layer. The sole remaining Bounce Run HUD
  hardcode now uses that same resolver.
- `createBrowserStaticExportZip()` remains the generic archive path and was not changed. Existing
  package tests continue to own ZIP32 rejection and unsafe-input behavior; the new real-app test
  proves the emitted production inventory against that contract.
- The final archive contains exactly six stored files: root `index.html`,
  `assets/index-BkpFlw_4.js`, the platform prefab, main scene, HUD document, and `favicon.svg`.
- Production source maps, TypeScript/source trees, unreachable assets, editor, React Flow, Monaco,
  QA hooks, compiler metadata, server code, and CDN imports remain excluded. The authoritative
  `production-qa-boundary.test.ts` was not weakened.
- No Chrome `requestfailed` stream was available or claimed. Server-side access logs and static URL
  scans are the evidence source.
