## Decisions and invariants

- Vite 6 documents production splitting through
  <https://v6.vite.dev/guide/build#chunking-strategy>; its relative-base module-preload behavior is
  documented at <https://v6.vite.dev/config/build-options#build-modulepreload>.
- Rollup documents both the `manualChunks` function and its side-effect-order warning at
  <https://rollupjs.org/configuration-options/#output-manualchunks>. The boundary therefore matches
  only the resolved `@dimforge/rapier3d-compat` package instead of a broad vendor-name matrix.
- The simpler object form was tried locally but not committed because the Bounce Run workspace does
  not directly resolve the transitive Rapier package as a config entry. The final function receives
  Rollup's resolved module IDs and yields exactly one `rapier-runtime` boundary.
- The entry statically imports Rapier and Vite emits a relative `modulepreload`; both chunks are in
  the HTML/import reachability closure. No lazy gameplay or changed initialization order was added.
- Total budgets remain `3.5 MB` minified / `1.2 MB` gzip. Measured largest-chunk budgets are
  `2.25 MB` minified / `850 kB` gzip after a `30.82%` / `24.14%` reduction from the prior single
  chunk.
- Production exclusions remain authoritative across every emitted JavaScript chunk. The static ZIP
  inventory is derived from all emitted files and separately proves that every JavaScript entry is
  reachable from the HTML module entry.
- Public production telemetry exposes frame time/FPS, entities, platform pool, and scheduler tick.
  It does not expose DEV QA effect/scheduler counters, so M13 committed scheduler/stabilization
  evidence remains authoritative for those contracts.
- `requestAnimationFrame` cadence generally follows the display/surface refresh rate:
  <https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame>. The installed
  Chrome-extension surface ran at 30 FPS and crossed the 25 ms alert; no standalone runner was used.
- No heap-byte budget is claimed. `performance.memory` is non-standard, deprecated, and unreliable:
  <https://developer.mozilla.org/en-US/docs/Web/API/Performance/memory>.
