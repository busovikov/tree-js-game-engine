# Handoff: UI-M1 version 2 model and runtime (complete)

## Objective

Replace the version 1 UI document contract with the complete version 2 schema and React-free DOM
runtime, migrate every unprotected repository consumer, and accept M1 with strict schema/runtime,
package-boundary, build, and user-Chrome evidence. M2 work is intentionally not started.

## Scope and acceptance criteria

- [x] Only `schemaVersion: 2` parses; version 1 remains a deliberate rejection case only.
- [x] Every required primitive, widget, container, and component instance has strict schema and
      native React-free runtime behavior.
- [x] Typed values/events, component expansion, sparse overrides, themes, assets, atomic mount,
      lifecycle, focus preservation, and deterministic locators are covered.
- [x] Instance override values match the source widget kind, range, step, maximum length, or
      declared option set; Radio group overrides remain internally consistent.
- [x] Override event slots are legal for the source kind and their referenced binding payloads
      match the source slot.
- [x] Checkbox, Radio, and Switch use explicit native label/control association; pointer and
      keyboard activation update state before emitting typed events.
- [x] Representative fixed, Hug, Fill, min/max, free, absolute, anchored, center, and scale layout
      behavior is deterministic. Combined center constraints preserve both axis transforms.
- [x] The standalone every-widget fixture is outside normal production entrypoints and captures
      wide/narrow user-Chrome evidence without exposing protected public assets.
- [x] No unprotected repository UI consumer emits or expects version 1; `@haku/ui` remains free of
      React/editor dependencies and the repository dependency gate is green.

## Decisions and invariants

- Version 1 has no reader, adapter, alias, fallback, or dual writer.
- Serialized containers are `frame`, `scroll-container`, and `list`; `container` occurs only in
  the deliberate version 1 rejection test.
- `UIRuntimeEvent.bindingId` replaces the old activation-only `eventId` surface.
- Programmatic value writes never dispatch user events; user state is committed before dispatch.
- Component descendants expose the top-level selectable ID plus source ID and instance path.
- Explicit label wrappers do not replace runtime control locators: `getElement`, instance locators,
  and stable `data-haku-ui-id` selection continue to resolve the native input.
- The dedicated M1 Vite config uses `publicDir: false` and its own HTML input/output. The ordinary
  playground build does not include the acceptance page.
- M0 `it.fails` markers remain owned by M3/M5 and were neither removed nor repaired in M1.
- Protected playground project/UI asset paths stayed excluded from reads, edits, staging, and
  commits throughout this continuation.
