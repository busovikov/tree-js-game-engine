# Handoff: UI-M5 complete layout and Inspector authoring

## Objective

Complete Milestone 5 with lossless Inspector authoring for the version 2 layout model, measured
Edit-mode canvas overlays, user-Chrome responsive/runtime parity, strict history behavior, and final
quality evidence without entering M6 or writing the protected playground project/UI assets.

## Scope and acceptance criteria

- [x] Expose Frame Free/Horizontal/Vertical/Grid, wrap, columns, four padding sides, distinct gaps,
      distribution, alignment, overflow, and clipping without JSON edits.
- [x] Expose Hug/Fill/Fixed, px/%, min/max, mode conversion, continuous history grouping, and
      invalid numeric rejection without NaN or transient invalid assets.
- [x] Expose Flow/Absolute placement, free-layout constraints, typography, fills, strokes, radius,
      opacity, image fit, accessibility, widget values/options, and compatible event bindings.
- [x] Reflect measured padding, applicable gaps, resolved insertion indices, overflow boundaries,
      and free-child constraints on the Edit canvas only.
- [x] Verify Inspector-only Grid/wrap and Hug/Fill/Fixed/minmax/constraints/overflow runtime parity at
      1280 × 720, 1440 × 900, and custom 480 × 720 with no unexpected Chrome console output.
- [x] Keep every mutation strict and undoable while leaving protected user paths untouched.

## Decisions and invariants

- Sizing and layout conversions preserve measured bounds as closely as possible, parse the complete
  document strictly before commit, and use the UI command bus rather than local serialized state.
- Unsupported Fill, percent, Absolute, widget, accessibility, and event combinations are disabled or
  rejected with explicit Inspector guidance; absent optional values remain absent instead of being
  coerced to defaults.
- Overlay geometry consumes serialized intent plus existing measured document-space bounds. It is
  pointer-inert, editor-only, absent from Preview and UI JSON, and never creates history.
- Padding uses four independent sides. Gap markers require applicable measured flow/grid neighbors.
  Overflow X is the bottom boundary and Overflow Y the right boundary, with policy-specific styles.
- Canvas creation/reorder owns insertion parent/index resolution; the overlay only presents that
  transient result and clears on cancel, leave, drop, or Preview.
- Browser acceptance used an unsaved in-memory built-in document with Save disabled. It never saved,
  reset, opened, formatted, staged, or committed either protected playground path.

## Completed

- Delivered strict sizing/layout adapters, conversion and grouped history, Frame controls, bounds,
  placement/constraints, lossless style/accessibility/widget/event fields, and measured overlays.
- User Chrome verified asymmetric padding `10/20/30/40` at Fit and exact 100%, Horizontal/Vertical/
  two-column Grid gaps `11/22`, and removal of false gap markers for an Absolute child.
- Real Chrome drags exposed root insertion indices `0`, `1`, and `3`. Cancel cleared the marker and
  added no command; one drop reordered one layer and exactly one Undo restored it.
- Chrome verified X Clip/Y Scroll and the swapped policies on distinct bottom/right boundaries,
  aligned left/top free-child constraint anchors, and complete overlay removal in Preview.
- Built a nested Inspector-only Horizontal+Wrap Frame with Fill width, Hug height, `240–520px`
  bounds, `8px` padding/row gap, `16px` column gap, and three `180×48` Fixed buttons.
- Empty numeric input reverted to `180` without history. Accessibility and style edits each passed
  Undo/Redo; incompatible undeclared events remained explicitly disabled.
- Reset the scratch state to the welcome screen, reset Chrome's viewport capability, finalized both
  agent-created tabs, and stopped the editor dev server.
