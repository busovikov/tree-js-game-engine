# Handoff: UI-M6 component masters and instances authoring

## Objective

Complete Milestone 6 with strict reusable UI component masters, instances, sparse overrides,
nested acyclic composition, runtime locators, atomic history, and user-Chrome evidence without
entering M7 or writing protected playground and Bounce Run paths.

## Scope and acceptance criteria

- [x] Preserve effective appearance when extracting a component and placing multiple instances.
- [x] Support allowed sparse overrides, field/reset-all controls, and forbid structural overrides.
- [x] Edit masters in an explicit scope while preserving type-valid instance runtime state and
      rejecting invalidating edits before history.
- [x] Detach to a visually equivalent concrete subtree with globally fresh IDs.
- [x] Support nested instances, reject direct and indirect cycles before mutation, and expose exact
      slash-separated runtime locator/source diagnostics.
- [x] Cover create, master edit, override, reset, nesting, and detach with atomic Undo/Redo.
- [x] Verify component deletion safeguards and an unreferenced component's exact atomic Undo/Redo.

## Decisions and invariants

- Component edit scope is editor-only state. Save always receives the strict real `UIDocument`,
  never selection, edit-scope, or Inspector projection metadata.
- Component masters may root at any valid UI element. Only serialized document roots require a
  Frame; component edit trees remain an in-memory Inspector projection.
- Instance overrides stay sparse and are keyed by stable source IDs. Structural edits happen only
  in the master; detach recursively materializes effective content with fresh IDs.
- Component dependency cycles, reference-breaking deletes, incompatible overrides, and invalidating
  master edits reject before mutation and do not consume history.
- Browser acceptance uses only unsaved in-memory built-ins with Save disabled. No project/UI JSON
  is edited to manufacture event or image preconditions.
